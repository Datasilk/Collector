# PostgreSQL Database

[Home](README.md) > PostgreSQL Database

Collector's schema lives in `Collector.SQL/` as plain `.sql` files — no
migration framework. Deploy runs `deploy.sql`, generated by `gulpfile.js`
from the folder layout:

```
Sequences/   CREATE SEQUENCE (first — tables use nextval() defaults)
Tables/      CREATE TABLE (topologically sorted on REFERENCES)
Indexes/
Functions/
Stored Procedures/
Views/       (optional)
data/        seed data (Blacklist.sql, DomainCollections-Countries.sql)
```

Full table inventory: [Database Schema](Schema.md).

## Deploying

`deploy.bat [dbname]` — default `collector`:

1. `npx gulp --database <name>` regenerates `deploy.sql`: creates the
   database if missing, `\connect`s, then includes every schema file via
   `\set f '...'` + `\i :f` (variable interpolation — required because
   psql treats quoted/spaced `\i` paths literally on Windows).
2. `psql -h localhost -U postgres -d template1 -a -e -f deploy.sql`.

`setup.bat` calls `deploy.bat Collector` with `PGPASSWORD` preset — no
prompts. Database names are case-sensitive: the app uses `Collector`
(connection string `Database=Collector`).

`npx gulp update-deploy` regenerates without deploying; `npx gulp watch`
regenerates on file change.

## Conventions

- All objects in `dbo`-style `public` schema; scripts are
  `CREATE ... IF NOT EXISTS` / `CREATE OR REPLACE` — reruns are safe.
- After adding/modifying scripts, publish via `deploy.bat` (manual, per
  project rules — no auto-migrations).
- Repositories live in `Collector.DAL` (Dapper), registered in
  `DapperStartupService.cs`; enums in `Collector.DAL/Enums`.
